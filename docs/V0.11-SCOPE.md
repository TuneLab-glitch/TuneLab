## Playback and Table Tracing — Added During the Approved Build

Jonny requested that the playing log trace relevant tables. Global Play/Pause, First/Previous/Next/Last, speed and Table Tracing controls follow the original recorded row across workspace navigation. Navigation no longer pauses playback; log/time/range/speed changes, timestamp resets and hidden-window events retain pause behavior. Tracing follows recorded inputs independently of tuning eligibility: MPR uses RPM and logged PA (or an explicitly labeled reference), Command uses RPM and reviewed pressure representation, AFM uses mapped frequency, Gear uses recorded gear/RPM and atmospheric inputs where applicable. Missing or out-of-bounds inputs clear affected markers without extrapolation. Markers are candidate locations, not ECU influence or sample eligibility.

Native tables and live My Workspace views trace the same point. Main/detached windows exchange lightweight row messages through the existing authenticated project/window channels, without reparsing logs or recalculating proposals. The editing window drives playback; viewing windows display the synchronized row. Existing Tracking/Coverage toggles remain independent. The custom-table observer only refreshes source table changes, not every playback readout.

Dedicated Edge tests verify moving markers on all four table types/custom views, missing/out-of-range clearing, toggle behavior, play/pause across tabs and detached cursor synchronization. v0.11 now has nine Edge suites and 14 pending UAT cases.

# v0.16 Whole-App Audit and Proposed Scope

2026-10-02. Planning deliverable; application code unchanged. v0.15 remains accepted: all 13 UAT scenarios passed. This audit does not imply new UAT acceptance or authorize every deferred feature.

## Conclusion

The largest demonstrated opportunity is interface hierarchy. The expanded global toolbar occupies 405 of 900 vertical pixels (45%) in the reference empty-state viewport. Primary work is pushed below repeated setup and status controls. Recommend nine coordinated workstreams below, preserving the calculation engine, evidence gates, saved projects, custom layouts and user menu order.

## Method and Limits

Inspected all 12 workspaces in headless Microsoft Edge at 1440×900, checked 900×700 overflow, reviewed source and user observations, and ran a synthetic 30,000-row timing probe. Applied first-time enthusiast, returning-user and experienced-tuner perspectives as a heuristic evaluation—not interviews or an observed usability study. Core v0.15 module bytes were checked against the delivered build. No full regression suite was rerun because application code was not changed.

Navigation probe passed for Log Review, AFM Scaler, Change Review and Settings: active class, aria-current and workspace agree. An extra screenshot highlight was hover, not a confirmed navigation bug. No JavaScript page errors occurred in the audit. No horizontal document overflow occurred at the two probed sizes; this does not establish all browser-zoom or accessibility behavior.

Timing results are one local synthetic run, not performance guarantees or a benchmark of a large private project. Cursor timings measure synchronous update calls, not end-to-end rendered frame latency. Workspace switch calls ranged approximately 6–32 ms. Startup was approximately 308 ms. DOM control counts include hidden controls and should not be interpreted as all simultaneously visible.

## Proposed v0.16 Workstreams

### 1. Compact Shared Toolbar (P1)

- Where: All Workspaces.
- Evidence: Measured: expanded toolbar is 405 px at 1440×900, before workspace content. Empty playback repeats several no-log messages.
- Change: Keep Search and Update All Proposals universally accessible. Use a compact transport by default, preserve full collapse/resize/popout, and place menu maintenance in navigation controls. Show one actionable empty state.
- Validation: Log Review → import a synthetic demo; confirm a chart is visible without scrolling at the reference viewport. Check expanded/collapsed persistence, keyboard access and browser zoom.

### 2. Playback Popout Recovery (P1)

- Where: Global Log Playback.
- Evidence: User observation: disconnected after navigation; source uses a 2.5-second heartbeat timeout. Background timer throttling is a hypothesis, not a reproduced cause.
- Change: Add Reconnect inside the popout, distinguish waiting from disconnected, and keep main-window playback as the single clock with validated session ownership.
- Validation: Pop Out Log Playback → Play → switch all workspaces → background main window → return; reconnect without a second clock. Test opener close and editing ownership changes separately.

### 3. Clear Current Proposal Review (P1)

- Where: Change Review.
- Evidence: User screenshot: already-reviewed acknowledgement leaves its action active. Code stores one signature acknowledgement, not a scrubbing journal.
- Change: Show Pending or Reviewed with timestamp. Disable the completed action until a relevant change; explain what changed. Distinguish proposal acknowledgement, historical checkpoint approval and destination verification.
- Validation: Change Review → review current proposals → scrub/play; acknowledgement stays reviewed. Change a proposal, mapping or evidence filter; show the appropriate pending reason.

### 4. Task-First Screen Hierarchy (P1)

- Where: Log Review / AFM Scaler / Boost Tables / Boost By Gear.
- Evidence: Measured: empty Log Review is about 4,799 px tall. Screenshot puts setup/status/import above the actual task. Long pages alone are not defects.
- Change: Place primary charts/tables first with a concise current-setup summary; disclose mapping, diagnostics and layout tools when needed. Keep analysis gates visible and retain deliberate advanced access.
- Validation: For each purpose, follow import → inspect → edit → review. Verify key task visibility, missing-channel recovery and unchanged numerical results.

### 5. Pressure Conversion as a Tool (P2)

- Where: Pressure Conversion / Table Unit Controls.
- Evidence: User finds little value in a dedicated navigation destination; it presents one source in two representations.
- Change: Move conversion beside relevant unit controls as an optional tool. Preserve old workspace IDs, saved layouts and search/deep-link access. Explain units and reference pressure explicitly.
- Validation: Open conversion from Boost Tables unit controls; verify bar/PSI values and unchanged source. Restore older projects and navigate legacy links.

### 6. One Guided Workflow (P2)

- Where: Guided Tutorial / Logging Strategy / Review Plan.
- Evidence: Source inspection: tutorial, purpose checklist, logging instructions and review plan coexist as separate entry points.
- Change: Use Guided Tutorial as the end-to-end route and link the other aids contextually. Keep logging instructions available, assuming an exported log. End with cautious paste-back verification and validation.
- Validation: Start Guided Tutorial for AFM, boost, startup and validation; check named routes, resume state, actionable prerequisites and destination verification.

### 7. Consistent Table and Chart Actions (P2)

- Where: Native Tables / My Workspace / Log Review.
- Evidence: Source inspection: wheel zoom exists for selected table containers; layout and zoom controls compete with task controls.
- Change: Standardize placement and labels for zoom, reset, Go To Trace and layout actions. Add discoverable gesture hints and keyboard alternatives; audit table eligibility rather than promise universal wheel behavior.
- Validation: Select a cell → wheel zoom → Go To Trace across supported native/custom tables. Check anchoring, chart click/drag distinctions, Escape and native browser zoom.

### 8. Contextual Feedback and Settings (P2)

- Where: All Workspaces / Settings / Project & Versions.
- Evidence: Screenshot: normal no-log state uses a prominent red outline; global unit/setup controls remain on unrelated screens. Settings combines multiple configuration domains.
- Change: Use neutral empty states, distinct actionable warnings and clear errors. Put field-specific recovery beside the field. Group Appearance, Workspace, Units/Review and Storage; explain saved project versus browser cache.
- Validation: Open with no log, then missing/ambiguous channels and stale proposals. Confirm each state and recovery is clear. Save/reopen a project and restore appearance inheritance.

### 9. Targeted Performance and Accessibility (P2)

- Where: Log Review / Project Restore / Shared UI.
- Evidence: Synthetic 30,000-row probe: import ~570 ms, restore ~1,483 ms, cursor mean ~1.5 ms. Source hover handler scans rows and is rebound during readout rendering; no hover bottleneck measured yet.
- Change: Profile hover, project restoration and visible trace rendering before changes. Reuse indexed ranges/handlers where evidence supports it. Check keyboard, focus, contrast, zoom and narrow layouts throughout cleanup.
- Validation: Compare the same fixtures before/after; include a larger synthetic log, active playback and populated tables. Verify correctness, focus after search, 200% zoom and no trapped controls.

## Deferred

Independent two-calibration comparison; additional vehicle/platform catalog expansion; automatic tune changes; live ECU actions; broad calculation-engine rewrite; a new history storage model; and unmeasured virtualization. Existing backlog remains separate. Prior unresolved KTuner full-precision axis evidence is not supplied by this audit.

## Delivery and UAT Requirements

Implement in order: compact shell and recovery → review clarity and conversion relocation → task hierarchy/help/actions → targeted measured optimization and accessibility. Preserve universally available Search and Update All Proposals. Do not silently hide blockers or interpret reviewed as vehicle-validated. Each UAT case must name its starting fixture, exact workspace/subsection, controls, visible checkpoints and persistence steps. Validate real browser presentation as well as calculation regression checks during the build.

Design references: [Nielsen Norman Group usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/) and [progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/). These support status visibility, recognizable actions and prioritizing core tasks; the TuneLab findings above come from local inspection.

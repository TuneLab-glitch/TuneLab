# TuneLab v0.16.2 Startup Loading

Startup splash blocks mouse and keyboard interaction until workspace restoration, default tables and UI preparation finish. Detached workspaces wait for synchronization or the existing disconnected recovery state. Initialization errors retain the splash with Reload TuneLab. Storage restoration errors show the existing recovery message in the usable app. No artificial percentage or minimum delay is used. This prevents premature interaction; it does not establish a startup speed improvement.

Verified in headless Edge: startup blocking, release after readiness, cached log restoration, and initialization failure recovery. Prior v0.16 UAT remains pending.

## User Testing

1. Open portable/index.html in the new v0.16.2 folder. While Loading tables and controls is visible, click or press Tab/Enter: underlying controls must not activate.
2. Once the splash disappears, open Boost by Gear: the six-gear Hondata starting template should be available without a log.
3. In Log Review, load a synthetic demo or an exported CSV, wait for browser workspace storage, then reload the same app file. The splash should remain during restoration; the saved log and tables should be available afterward.
4. From Workspace Window and Panel Options, open a detached workspace. It should become usable after synchronization, respecting the current editing owner.

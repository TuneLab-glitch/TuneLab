`npm run test:browser` additionally requires a development Playwright installation. `TUNELAB_PLAYWRIGHT_MODULE` can point to an existing installation, `TUNELAB_BROWSER_EXECUTABLE` selects an installed browser, and `TUNELAB_BROWSER_OUTPUT` selects a temporary artifact directory. ## Decisions and limits

Only one window edits at a time. The main window coordinates project identity, revisions and explicit handoff over document-bound MessageChannels (after source/token/origin handshake); stale commits are rejected rather than merged. The editing window retains its selection and controls across acknowledgements, queues subsequent changes, and flushes pending actions before handoff. A viewing window can download the shared project. Native browser windows may require popup permission.

Main and detached arrangements are saved separately per workspace in v0.7 JSON. Grid preferences are also cached locally when browser storage is available. v0.3–v0.6 imports remain supported, older card sizes migrate, and opening a file clears calibration confirmations. v0.7 backups are not promised to open in older releases; retain original backups.

If main closes/reloads, detached windows pause and offer recovery JSON; reopen it in a main window and open new workspace windows. There is no automatic reconnection or owner promotion. Save before closing a window with unfinished actions; browser unload delivery is not guaranteed. Browser IndexedDB remains a log-library store rather than a complete project backup. Parsing/serialization still run on the main thread, so large multi-log projects can take time to synchronize.

## KTuner export finding

The supplied CSV revealed `Time(s)` / `ECT(F)` / `MAP(mBar)` spellings. The parser accepts no-space timestamp unit headers; mapping suggests only explicit time/coolant/MAP units, including mbar conversion to kPa. `TPS`, `MAF.v`, separate STFT/LTFT, `LAM`, `LAM.ADJ` and categorical `FUEL.STAT` are not silently assigned to pedal, frequency, combined trim, AFR/command or numeric status conventions. Unknown platform remains unknown until user review.

Width-mismatched rows remain rejected rather than padded or shifted into declared channels. Import now shows a visible rejection-count warning while preserving the full original CSV. Passing rejection/retention tests does not mean this malformed export is a valid analysis fixture. Neither native `.kdlg` nor either user's CSV is bundled.

The second user-supplied KTuner CSV has 30 headers and 2,938 matching rows, with `Time(s)`, `RPM`, `MAP(mBar)`, `ECT(F)` and `GEAR` recognized. Its full raw text and mapping/unit provenance survive save/reopen. Jonny explicitly prioritized header structure; no claim of a useful tuning baseline, stable operating run or Civic ECU equivalence is made from this log. The first malformed export remains separately documented and rejected by width; the second file is not used to guess the first file's missing header alignment.

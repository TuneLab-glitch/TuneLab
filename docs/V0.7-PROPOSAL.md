# v0.7 proposal — workspace organization and separate windows

Status: approved by Jonny on 2026-10-02 ("Lets do it"), including the subsequent drag-and-snap panel request. Navigation, single-workspace windows, coordinated editing and movable grids are the build scope. The first Fit/KTuner CSV has a structural mismatch; the second verifies CSV/header structure. Full analysis verification remains gated on appropriate channels and reviewed semantics; optional table shading is deferred.

## Recommended scope, in priority order

1. **Navigation cleanup.** Remove numeric prefixes. Keep named items in a collapsible sidebar for fast switching; use a workspace dropdown in narrow or collapsed layouts. Preserve the current workspace and provide clear focus/keyboard navigation. A desktop dropdown alone would hide available workspaces and add a click to every switch.
2. **Single-workspace windows.** Add an Open in new window action for each workspace. The separate window contains that workspace, its relevant controls and compact project/log/unit context, with no sidebar or unrelated workspaces. Include Return to main workspace and a clear disconnected state.
3. **Reliable shared project state.** Treat this as part of separate-window delivery, not a later enhancement. Windows edit one project through a coordinating owner; edits carry project identity and revision, and stale/conflicting changes are rejected visibly. Preserve manual refinements, protection and history. Define owner-window closure, reload, project switching, popup blocking and save responsibility. Never let separate windows silently overwrite each other or use differing units. Check both local-file launch and browser storage/origin limitations before selecting the communication mechanism.
4. **Finish real KTuner compatibility verification.** Inspect the forthcoming original export and verify headers, units, time, missing values, status/mixture meanings and destination paste behavior. Implement only evidence-supported mapping corrections. Preserve raw data and reviewed provenance. Current Hondata acceptance is retained as regression coverage.
5. **Readable table colors and change shading.** Add optional value gradients with a visible legend, colorblind-friendly and no-shading modes, a shared source/proposal scale and zero-centered delta display. Keep scales stable during edits; protect selection/warning/protection meanings. Values and legends must remain readable without relying on color. Keep advanced min/max/outlier controls for a later iteration unless needed for acceptance.

Items 1–3 and movable panels below form the delivered release. Item 4 has successful header/import/retention evidence for the second export and explicit rejection evidence for the first; full analysis needs appropriate channels/semantics. Item 5 is deferred to keep this round focused. Avoid adding the full advanced viewer to this release.

## Acceptance scenarios

- Open Boost, AFM and Log review separately; each window shows only its workspace and required context.
- Edit protected/unprotected cells, change display units and select logs in either window. Every window shows the same project revision and retains manual edits/history.
- Attempt simultaneous edits and edits from a stale window; conflicts are explicit and recoverable.
- Switch projects, reload or close the coordinating window, block popups, and save/reopen. No cross-project mixing or lost updates.
- Confirm local-file operation and backup/download behavior with multiple windows.
- Navigate with mouse and keyboard in desktop and compact layouts.
- If shading ships, verify the same physical source/proposal values use the same scale and remain legible with shading disabled.
- Verify the original KTuner export separately from synthetic fixtures and retain Hondata regressions.

## Approved panel organization

Charts, table previews and evidence cards can be dragged by a dedicated handle into ordered grid slots with a highlighted placement target. Half/full-width controls, existing resize/collapse/expand controls, keyboard move buttons and Alt-arrow movement remain available. Each workspace stores its own arrangement; main and detached windows have separate layouts included in v0.7 JSON. Reset panel layout restores the workspace default. Narrow layouts use one column.

Navigation, project/log context, primary action bars, settings and tightly coupled import/input groups stay anchored. Moving a card must preserve its DOM controls and existing calculation handlers.

## Shared-window implementation decision

Use one editable window at a time with an explicit **Edit in this window** handoff. All windows view the shared project. The coordinating main window grants editing after pending actions and edits finish, checks project identity and revision on every commit, and rejects stale submissions. This resolves concurrent-write conflicts without automatic merging. Changes queue behind acknowledgement; editing pauses during handoff.

Save project remains available in viewing windows. If the main window closes or reloads, detached windows pause and offer a recovery JSON download. Reopen that backup in a main window and open new detached workspaces. No automatic owner promotion or automatic reconnection to a newly opened project is included. Save before closing a window with unfinished actions.

## Panel acceptance

- Drag cards by their handle; tables retain normal selection gestures. Check placement highlight, ordering, half/full width, native resizing and collapse/expand.
- Move with buttons and Alt-arrow keys; focus follows the handle.
- Save/reopen main and detached arrangements independently; reset one workspace without changing another.
- Confirm narrow layouts remain readable and anchored controls cannot be dragged.
